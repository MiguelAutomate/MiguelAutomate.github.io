Abstract

This document specifies the complete end-to-end architecture of ZeroSilence AI, an autonomous agentic security-as-a-service platform designed to detect and remediate control-flow vulnerabilities in LLM agent frameworks. The core design principle is the No-Silent-Failure Invariant: no exception, malformed response, or unexpected state may be absorbed without an explicit, typed, and routed decision. We achieve this through five governing principles, a message-driven architecture with asynchronous coordination, lock-free state machines, typed error taxonomies, and comprehensive failure recovery strategies.

This specification includes (1) formal architecture overview with seven independently-failing modules; (2) closed error taxonomy with exhaustiveness-checked routing; (3) complete module pseudo-code for M-01 (Webhook) through M-07 (Telemetry); (4) explicit FSM definition with no implicit state transitions; (5) BigQuery schema for audit trails and compliance; (6) a catalog of 12+ failure modes with detection and recovery strategies; (7) verification methodology using property-based testing, fault injection, and chaos engineering; (8) a 4-phase implementation roadmap; and (9) a Phase 3 extension covering coverage-guided fuzzing, dynamic discovery, and patch verification.

Section 06

Data, Schema & Audit-Trail Design

Every FSM transition, every error event, and every patch decision is recorded as a structured log entry in GCP BigQuery. This immutable audit stream serves multiple purposes: it is the system's memory of its own failures, the evidence for XPRIZE compliance, and the operational telemetry backbone for dashboards and alerting.

6.1 ScanRecord Schema (BigQuery)

The main table: one row per PR scan, immutable after creation, updated via DML for state transitions.

Column Type Description Partition / Cluster
scan_id STRING (UUID) Primary key: idempotency ID for this scan. Hash of (org/repo/pr_number/commit_sha). Partition Key
pr_url STRING GitHub PR URL: github.com/owner/repo/pull/{number}. Clustered
owner STRING Repository owner (org or user). Clustered
repo STRING Repository name. Clustered
pr_number INT64 PR identifier within repo.
head_commit_sha STRING Commit SHA of PR head at time of scan.
current_state STRING (ENUM) FSM state: QUEUED | SCANNING | FOUND | PATCHING | DELIVERING | DELIVERED | FAILED | ESCALATED.
state_version INT64 Monotonic version counter for optimistic concurrency.
findings_count INT64 Total vulnerabilities detected in this scan.
findings_json JSON Array of Finding objects (§6.2).
error_events ARRAY<STRUCT> Stack of errors that occurred (oldest first). See §6.3.
created_at TIMESTAMP When the scan was first queued. Partition Key
updated_at TIMESTAMP Last state transition timestamp.
completed_at TIMESTAMP (NULL) When terminal state reached (DELIVERED, FAILED, or ESCALATED).
